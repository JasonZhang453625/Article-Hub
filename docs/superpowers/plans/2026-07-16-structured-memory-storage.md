# Structured Memory Storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Markdown-as-source-of-truth summaries with versioned structured memory JSON while preserving all existing Hive data, full-text saves, backup/sync compatibility, display, and retrieval behavior.

**Architecture:** Add a typed `MemoryDocument` domain model whose JSON-compatible map is stored in a new nullable `ArticleAdapter` field. Existing `summary` records remain readable through compatibility getters; new AI/full-text writes use `MemoryDocument`. AI returns structured JSON, while Markdown and retrieval text are derived locally.

**Tech Stack:** Flutter/Dart, Hive hand-written adapters, Riverpod, `dart:convert`, `uuid`, `flutter_markdown`, Flutter test.

## Global Constraints

- Preserve Hive `Article` type ID 0 and every existing field number; add only new nullable fields.
- Do not modify or discard unrelated dirty-worktree changes, especially retrieval-isolate work.
- Key-point IDs and order are generated by the client, never by the LLM.
- Keep article-level vector indexing working; key-point vectors remain a later derived index.
- Backups and encrypted sync payloads must read legacy flat Article JSON and write the new nested schema.
- Vector data remains derived and outside Article backup/sync payloads.
