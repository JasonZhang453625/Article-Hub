## 1. 产品定义

### 1.1 一句话定位

记忆海是一个本地优先的 **仿生记忆提取工具**：

> **一键分享即知识化。对话即联想检索。原文始终可追溯。**

人不靠全量存储来记忆。大脑自动过滤噪声、提取结构、保留概念，需要时通过联想唤起。记忆海把同样的认知逻辑应用到数字内容上——从"存更多"切换到"只记该记的，随时想得起"。

用户从微信、知乎、Bilibili、小红书、X、YouTube 等平台把链接分享到记忆海。应用先可靠接收内容，再自动提取信息、生成统一的 AI 记忆知识卡片、添加标签并建立本地索引。用户回到应用时，不需要翻找收藏夹，而是直接在首页向自己的全部知识库提问。

### 1.2 核心闭环

```text
跨平台分享链接
  → 待处理箱
  → AI 记忆知识卡片
  → 自动标签 + 文件夹建议
  → 本地向量索引
  → 首页全库对话
  → 引用知识卡片
  → 原文追溯
```

该闭环解决的不是“如何保存更多链接”，而是：

> **如何模拟人类记忆方式——过滤噪声、提取关键、建立联想——把散落内容转化为在需要时能被再次发现和使用的个人知识。**

### 1.3 产品原则

1. **收集永不失败**：分享后立即保存，像大脑第一时间捕捉到刺激。AI、网络或正文提取失败只进入待处理箱，绝不丢失。
2. **信息密度最大化**：不存噪声，只保核心。V2.0 首版中一篇内容对应一个 AI 记忆知识卡片，也对应一个检索 chunk——从原页面到记忆颗粒的压缩。
3. **对话必须可追溯**：回答必须基于知识库记忆，并附带可点击引用；记忆中没有答案时必须明确说明——记错了比记不住更危险。
4. **本地优先、用户控制 AI**：内容、向量索引和处理状态默认保存在设备本地；AI 请求直连用户配置的模型服务。登录后的同步是可选能力，文章与完整 AI/Embedding 配置通过 HTTPS 同步到用户账号。
5. **自动化不剥夺控制权**：AI 标签和文件夹分类自动写入并允许编辑；文件夹分类匹配现有文件夹或在必要时新建，但用户始终可以手动移动或重命名。
6. **原文始终保留**：知识卡片替代原页面作为默认阅读入口，但不能替代事实来源；用户始终能打开原页面——记忆可以压缩，但不能失真。

### 1.4 首发用户

首发面向 **所有重度收藏用户**：

- 每周从多个平台保存大量文章、视频或帖子；
- 经常出现“存过，但想不起来在哪里”的情况；
- 希望减少手工整理，同时仍能控制自己的数据；
- 愿意配置自己的 AI 服务，或先把内容放入待处理箱后再统一处理。

专业技术、研究和知识工作者是优先验证 AI 价值与商业化的种子人群，但产品入口与基础流程不限定职业。

## 2. 差异化与边界

### 2.1 差异化

RAG、记忆和语义检索本身不是独有能力。记忆海 的差异化来自这些能力组成的完整工作流：

| 维度 | 记忆海 的重点 |
|---|---|
| 收集入口 | 作为移动系统分享目标，被动接收来自中文互联网与通用网页的链接 |
| 内容处理 | 把不同平台的原页面转成统一、简洁、可检索的知识卡片 |
| 检索范围 | 默认对整个个人知识库提问，不要求先创建 notebook 或选择资料集 |
| 数据控制 | 本地存储、本地索引、BYOK、无 记忆海 自有 AI 后端 |
| 证据链 | AI 回答引用知识卡片，知识卡片继续回链原页面 |
| 记忆共享 | 导出标准记忆包，可跨 App 分享、供 Agent 加载；所有权归用户 |

NotebookLM 等产品擅长对用户主动组织的一组来源进行深度研究；Readwise 等产品擅长阅读、标注与全文检索。记忆海 优先解决的是：**跨平台内容进入个人记忆之前的低摩擦收集、仿生提取和全库联想召回。**

### 2.2 非目标

- V2.0 首版明确不做：

- NotebookLM 式的项目型多源研究工作台；
- 基于全文切块的深度事实问答；
- 通用互联网搜索或自动发现外部资料；
- 播客、PPT、报告等多模态内容生成；
- 记忆海 托管的 AI API、集中式内容后端或默认行为追踪；
- (已升至 P0)；
- 长期聊天记录与跨会话记忆。

上述能力只有在“分享 → 知识化 → 全库召回”核心闭环通过行为数据验证后，才重新评估。

## 3. 当前状态与目标状态

### 3.1 当前已实现

截至 2026-07-10（V2.0.17），应用已经具备：

- 本地 Hive 存储，保留 `'passages'` box 兼容历史数据；
- 识别 11 类来源平台；
- 手动添加、批量 URL 添加、剪贴板链接检测；
- Android 系统分享接收；
- 自动抓取页面标题与封面；
- 正文提取与 BYOK AI 记忆；
- 记忆知识卡片页与原页面 WebView；
- 标签、备注、收藏、文件夹与嵌套文件夹；
- 本地搜索、来源筛选、自定义筛选组；
- JSON 全量备份与恢复，备份排除 AI API Key；
- 中英文多语言支持与 AI 记忆语言指令注入；
- 字体大小与 WebView 缩放可调；
- 来源平台排序、隐藏与首页筛选栏拖拽重排；
- 记忆反馈字段（summaryFeedback）；
- 全局入场动画（DelayedReveal）；
- 处理状态机（processingStatus / processingStage / processingError / retryCount / lastProcessedAt / suggestedFolderId 历史遗留字段），旧数据自动降级为 completed；
- 先保存再处理的分享流程，URL 去重，后台 pipeline 异步处理；
- 进程页（原“待处理箱 / Inbox”），按状态分组，支持重试与删除，前台恢复自动重试；
- 5 阶段处理流水线（metadata → content → summary → auto-tags → auto folder classification）；
- 自动标签写入（不覆盖用户编辑）与自动文件夹分类（匹配现有文件夹或自动新建，写入 `folderId`）；
- MiMo / DeepSeek / GPT-5 / o1 / o3 / o4 等模型的兼容（按模型只发送一个 token 上限字段，必要时关闭 thinking，并剥离 `<think>` 标签）；
- 知识库文件夹过滤 chip：点击文件夹页条目即可按文件夹查看知识库，过滤可见可清除；
- 元数据封面回退：OG/Twitter 标签缺失时从正文 `<img>` 中挑选第一张有效图片；
- 旧文章批量知识化入口（Settings 页，显示条数与确认）；
- Embedding 配置（独立 baseUrl / apiKey / model），API Key 不进入备份；
- 本地向量索引（Hive 独立 box, typeId=6），一篇一记录，增量更新与全量重建；
- 向量相似度召回（cosine similarity, top-k, 最低门槛）与关键词降级；
- 四入口底部导航（Chat / Knowledge / Progress / Settings），StatefulShellRoute；
- RAG 对话首页：查询 → 召回 → 候选记忆 → AI 回答 + 引用知识卡片，信息不足时拒绝编造。

### 3.2 当前关键缺口

- iOS 分享入口尚未完成；
- 记忆质量看板与索引健康检查尚未实现；
- iOS 分享入口、跨会话长期记忆与端侧 embedding 尚未实现；
- 记忆质量看板、召回透明度与本地质量诊断尚未实现；
- 第三方 OAuth、真机双设备同步验收、冲突副本裁决与云端向量索引同步尚未完成；
- PDF/图片导入、Agent 自主任务和商业化仍为后续能力。

### 3.3 V2.0 目标状态

| 维度 | Phase 0 基线 | 当前（Phase 1-3） | Phase 4+ 目标 |
|---|---|---|---|
| 首页 | 列表、搜索、筛选 | **四入口导航**：Chat（RAG 对话）/ Knowledge / Inbox / Settings | 记忆质量看板、索引健康检查 |

## 4. 信息架构

移动端主导航默认为四个入口（支持设置中隐藏"进程"入口）：

| 入口 | 核心任务 |
|---|---|
| **对话** | 向全部已知识化内容提问，查看带引用的回答 |
| **知识库** | 浏览、搜索、筛选、编辑知识卡片，管理标签和文件夹 |
| **进程** | 查看处理中、失败和等待配置 AI 的内容，执行重试或删除 |
| **设置** | 配置 AI/embedding、隐私、备份、显示和索引管理 |

手动添加入口放在知识库页或全局快捷入口。文件夹、标签和传统关键词搜索属于知识库能力，不与对话首页争夺主入口。

## 5. 核心用户流程

### 5.1 分享并知识化

1. 用户在其他 App 中点击“分享至 记忆海”。
2. 记忆海 立即保存 URL、来源、接收时间和可用元数据，并显示保存成功。
3. 新条目进入待处理箱，按顺序执行正文提取、记忆生成、自动标签、文件夹建议和 embedding。
4. 全部必要步骤成功后，条目从待处理箱进入知识库。
5. 任一步骤失败时保留条目、失败阶段和错误原因，允许后台或手动重试。

### 5.2 向知识库提问

1. 用户在对话首页输入主题词或具体问题，例如“汽车”或“我收藏过哪些关于新能源汽车竞争格局的观点？”
2. 系统从本地索引召回相关记忆；embedding 不可用时降级为关键词召回。
3. 系统把候选记忆发送到用户配置的聊天模型，要求只基于候选内容回答。
4. 页面展示回答和引用知识卡片。
5. 用户可以打开知识卡片、查看原页面，或反馈答案是否有用。

### 5.3 信息不足

如果召回为空，或候选记忆不包含回答所需事实：

- 不生成看似确定的答案；
- 明确提示“当前知识库记忆中没有足够信息”；
- 在存在弱相关内容时展示相关卡片；
- 提供打开原文或调整问题的入口。

### 5.4 导出与共享记忆

1. 用户在知识卡片页或知识库批量选择需要导出的条目。
2. 系统将知识卡片、标签、文件夹结构打包为 JSON 文件。
3. 导出文件通过系统分享菜单发送到目标 App 或联系人。
4. 接收者可将记忆包导入自己的记忆海实例，或供外部 AI Agent 加载为知识库。
5. 导出的内容是用户提炼后的知识结构（记忆、标签、分类），不包含原始平台数据。分享授权、范围和用途由用户完全控制。

## 7. 产品与数据契约

### 7.1 Article 兼容性

- 保留现有 `Article` 类名和 Hive typeId `0`。
- 保留历史 Hive box 名称 `'passages'`。
- 现有 `Article.summary` 继续作为首版唯一规范化知识 chunk。
- 新字段必须继续使用手写 `TypeAdapter`，并以空值兼容旧数据。

已新增的处理状态字段（V2.0.0，Phase 1.1）：

- `processingStatus`：`ProcessingStatus` 枚举（pending / processing / completed / failed），默认 completed；
- `processingStage`：`ProcessingStage` 枚举（metadata / content / summary / tags / folderSuggestion / indexing），可空；
- `processingError`：`String?`，失败原因；
- `retryCount`：`int`，默认 0；
- `lastProcessedAt`：`DateTime?`，最后处理时间；
- `suggestedFolderId`：`String?`，AI 建议的文件夹 ID。

Hive field 编号 13-18，旧数据自动降级为 completed / null / 0。

未来 Article 还需要支持：

### 7.2 索引契约

- 向量输入：`title + summary + tags`。
- 索引记录至少包含 `articleId`、embedding 模型标识、内容指纹和向量。
- 索引是派生数据，可删除、可重建，不进入 JSON 备份。
- Article 删除或记忆变化后，旧索引不得继续被召回。

### 7.3 AI 回答契约

对话结果至少包含：

- 回答正文；
- 使用的 `articleId` 引用列表；
- 是否因信息不足而降级；
- 本次使用的召回方式：语义或关键词。

模型输出中的未知 articleId 必须被过滤，不得生成失效引用。

## 8. 非功能需求

- **可靠性**：分享接收成功后必须先持久化再处理；后台失败不能丢失条目。
- **性能**：对话提交后先快速展示检索状态；本地召回不因知识库规模增长而阻塞 UI。
- **离线**：离线时可收集、浏览、管理和关键词搜索；AI 与 embedding 显示等待状态。
- **隐私**：无 记忆海 自有内容后端；用户内容只发送到用户主动配置的 AI 服务。
- **成本控制**：批量记忆、重新索引和模型切换前提示潜在 API 成本。
- **兼容性**：Hive schema 向后兼容；Android、iOS、Web、Windows、macOS 保持可构建。
- **可访问性**：关键触控目标不小于 48×48，状态和错误不能只依赖颜色表达。
- **平台适配**：状态栏文字颜色根据应用背景亮度自动反转 — 浅色背景时使用深色文字（或浅色指示条），确保始终可见。

## 9. 成功指标

### 9.1 北极星指标

**每周成功知识召回次数**

一次成功知识召回应同时满足：

1. 用户通过对话提交问题；
2. 系统生成带有效引用的回答；
3. 用户通过“有用”反馈或点击引用知识卡片表达结果具有价值。

### 9.2 配套指标

| 指标 | 用途 |
|---|---|
| 分享后持久化成功率 | 验证收集动作是否可靠 |
| 知识化完成率与中位耗时 | 验证处理流水线 |
| 待处理失败率与积压量 | 发现模型、网络和提取问题 |
| 记忆有用率 | 验证知识卡片质量 |
| 对话无结果率 | 判断记忆召回覆盖度 |
| 回答有用率 | 判断 RAG 回答价值 |
| 引用点击率 | 判断回答是否推动用户继续使用知识 |
| 关键词降级占比 | 判断 embedding 兼容性 |

指标默认保存在设备本地。需要汇总研究时，由用户主动参与测试或导出匿名统计，不引入默认行为追踪。

## 10. 调研证据与新押注

2026-06-02 的 107 份问卷验证了：

- 收藏分散与保存后很少回看是普遍痛点；
- 文件夹标签和系统分享保存是高优先需求；
- AI 记忆整体意愿一般，但在技术与研究人群中更高；
- 59% 用户偏好本地与 AI 可切换，支持本地优先与 BYOK。

完整分析见 [`调研分析报告.md`](./调研分析报告.md)。

本 PRD 的 AI-first 方向是一次新的产品押注：它不再把 AI 仅作为可选记忆按钮，而是把“仿生记忆提取与再次联想召回”作为产品主价值——模拟人脑“过滤噪声、提取结构、联想唤起”的认知闭环。现有问卷只验证了意愿与痛点，尚未验证用户是否会持续通过对话找回知识。因此，Phase 1–3 必须用真实行为指标验证，不能把方向判断当成已经成立的事实。

## 12. 商业模式

记忆海当前处于免费阶段，专注于验证核心闭环。商业化遵循"核心永久免费、高级能力付费"原则：

### 12.1 免费层（永久）

- 本地知识化流水线（无限制）；
- 本地向量索引与 RAG 对话（无限制）；
- BYOK 使用自有 AI API（无限制）；
- JSON 备份导出/导入；
- 基础 Agent 能力（单次主题综述）。

### 12.2 订阅层（Memora Pro）

| 能力 | 定价逻辑 |
|---|---|
| 多端同步 | 含账号云端存储与多设备自动同步 |
| API 配置包订阅 | 预配置的主流 LLM API（无需用户自备 Key），按月调用额度 |
| 笔记/知识卡片上限扩展 | 本地无限制，但云端同步超出基础容量后需订阅 |
| 高级 Agent | 自动推送、定时综述、知识库健康诊断 |
| PDF/图片导入 | 高级文件格式处理能力 |

### 12.3 广告模式（远期备选）

- 融入式广告：在知识库浏览流中穿插原生广告，仅面向免费用户；
- 广告不与用户知识数据关联，不做行为定向；
- 订阅 Pro 可去除广告。
