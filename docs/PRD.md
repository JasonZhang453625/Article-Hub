# Article-Hub 产品需求文档（PRD）

> 版本：v2.0 规划 · 文档状态：草案 · 最后更新：2026-06-02
> 当前应用版本：V1.5.0（纯本地 Hive 存储）

> 📊 **本版优先级已依据用户调研调整**：基于 107 份有效问卷（详见 [`调研分析报告.md`](./调研分析报告.md)），核心痛点假设获验证，但功能优先级有重大修正——**组织/录入类基础功能上调、AI 摘要重定位为面向专业用户的付费能力、云同步下调**。受调研支持/修正的条目在下文标注 📊。

---

## 1. 产品概述

### 1.1 一句话定位
Article-Hub 是一个跨设备的「文章收藏 + AI 阅读中枢」：用户从 X、Bilibili、小红书、微信、知乎、ChatGPT、YouTube 等平台粘贴链接保存，应用自动识别来源、提取正文，并用 AI 生成摘要，让用户无需打开原页面即可读完核心内容。

### 1.2 从 V1.5 到 V2.0 的演进
| 维度 | V1.5（现状） | V2.0（目标） |
|------|-------------|-------------|
| 数据 | 纯本地 Hive，单设备 | 云端同步 + 本地离线缓存，多设备 |
| 账号 | 无 | 账号体系（登录/注册） |
| 阅读 | 内置 WebView 打开原页面 | AI 正文提取 + 摘要，原页面作为兜底 |
| 组织 | 来源筛选 + 标签 + 自定义筛选组 | 文件夹 + 嵌套标签 + 批量操作 + 强检索 |
| 导入 | 手动粘贴单条 | 系统分享菜单接收、批量导入、书签导入 |

### 1.3 目标用户
- 重度信息消费者：每天从多个平台收集文章/视频/帖子，需要统一沉淀。
- 跨设备用户：手机收藏、平板/桌面阅读。
- 时间紧张的读者：希望先看 AI 摘要再决定是否精读。

### 1.4 平台重心
**移动优先**（Android / iOS）。桌面（Windows/macOS）与 Web 保证可用、做响应式适配，但不深度优化。

## 2. 现状能力盘点（V1.5.0 已实现）

- 粘贴 URL 自动识别 11 个来源平台（微信/知乎/X/B站/小红书/ChatGPT/YouTube/Medium/Substack/Reddit/Web）
- 保存标题、标签、备注、收藏、时间戳，本地 Hive 持久化
- 按来源筛选 + 跨标题/标签/备注/URL 全文搜索
- 自定义筛选组（按标签关键词 + 来源组合）
- 内置 WebView 阅读器（移动 UA、缩放、进度条、深链拦截）+ 系统浏览器兜底
- 来源平台 chip 可拖拽排序、可隐藏
- 浅色/深色/跟随系统主题、全局字号调节、Web 缩放调节
- 精致的页面转场与列表逐项揭示动画

## 3. V2.0 需求详述

需求按四大能力方向 + 数据/账号基础设施组织，每条标注优先级（P0 必须 / P1 重要 / P2 增强）。

### 3.1 数据与账号基础设施

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| INF-1 | 账号体系 | P0 | 邮箱/第三方登录，匿名本地模式可平滑升级为登录账号（本地数据迁移上云，不丢失） |
| INF-2 | 云端同步 | P1（↓） | 📊 **调研下调**：整体仅 30% 选为最想要功能，且只用手机者仅 23%、桌面用户达 59%——需求集中于桌面场景（样本占 16%）。文章/标签/文件夹/设置跨设备同步；本地 Hive 作为离线缓存层。建议后移，先服务核心移动场景 |
| INF-3 | 离线优先 | P0 | 无网络时可读写本地缓存，联网后增量同步，冲突按「最后修改时间」合并 |
| INF-4 | 本地导出/导入 | P0 | JSON 全量导出与导入，作为云之外的兜底备份（同时修复现状"卸载即丢数据"风险） |
| INF-5 | 同步状态可视 | P1 | UI 显示同步中/已同步/失败/离线，失败可手动重试 |
| INF-6 | 隐私与同意 | P0 | 首次开启云同步/AI 时明确告知"URL 与正文将上传至云端/AI 服务"，需用户主动同意 |

### 3.2 AI 能力（本版核心差异化）

> 📊 **调研修正**：AI 摘要整体意愿仅 5.42/10（8选3 排名第三），但分人群差异显著——互联网/技术从业 6.58、研究/知识工作者 5.65，而学生仅 3.56。结论：**AI 摘要不降级、但改打法**，从"全民功能"重定位为**面向专业知识工作者的付费亮点**，不追求全民渗透。其工程优先级让位于组织/录入类基础功能（见 3.3）。

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| AI-1 | 正文提取 | P0 | 抓取链接正文（去广告/导航），是 AI 摘要的前置依赖；失败时回退到 WebView |
| AI-2 | AI 摘要 | P0 | 为每篇文章生成结构化摘要（要点列表 + 一句话总结），**让用户不必打开原页面** |
| AI-3 | 摘要时机 | P1 | 支持保存时自动摘要 / 手动触发两种模式，用户可在设置中选择（自动模式注意 API 成本） |
| AI-4 | 摘要缓存 | P0 | 摘要结果随文章存储并同步，避免重复消耗 token |
| AI-5 | AI 问答 | P2 | 针对单篇文章追问（"这篇的核心论点是什么"），多轮对话 |
| AI-6 | 多语言摘要 | P2 | 摘要语言可选（跟随原文/中文/英文） |
| AI-7 | 模型选择 | P1 | 默认最新 Claude（Opus/Sonnet 4.x）；长文用大模型、短文用快模型以控成本 |

> ⚠️ 工程依赖：AI-2 依赖 AI-1 的正文提取质量；正文提取对微信/小红书等反爬平台难度高，需评估服务端抓取方案。

#### 3.2.1 AI Key 存储决策（威胁模型分析）

**结论：key 明文存于本地 Hive，不做额外静态加密；唯一防护是「备份导出排除 key」。**

| 攻击场景 | 明文 Hive | Keychain/Keystore 加密 | 是否值得加密 |
|----------|----------|----------------------|-------------|
| App 联网泄露 | 不联网（直连用户自己的 AI 提供商） | 同 | 无差别 |
| 物理拿到**已解锁**设备 | 能读 | 解锁后也能读 | 无差别 |
| 物理拿到**未解锁**设备（无 root） | app 沙箱内 | 同样沙箱内 | 无差别 |
| 物理 + **已 root/越狱** | 直接读 | 需多一步，专业破解仍可拿 | 边际防护 |
| **备份文件外泄**（分享/上传） | **明文泄露** ✗ | key 不在备份 ✓ | **唯一真实差异** |

理由：威胁模型是「攻击者拿到已解锁设备或 root 权限」，此场景下 app 内加密无实质防护（解密路径就在同一 app 内，且原生 Keychain 在解锁设备上同样可被同 app 读取）。真正有意义的防护是防止 key 随可分享的 JSON 备份外泄——已落地于 `AppSettings.toJson`（排除 `aiApiKey`）并有回归测试守护。

**历史教训**：曾尝试用 `flutter_secure_storage` 加密，但其 web 子包依赖 `dart:html`/`dart:js_util`，与 Flutter 3.41 默认 Wasm 渲染器不兼容，导致 web 端白屏。权衡加密的边际收益 vs. web 不可用 + 多平台条件导入的工程复杂度后，回退为明文本地存储。这与 ROADMAP AI-8 的原始措辞（「不得明文落盘」）不一致，已同步更新 ROADMAP。

## 4. 非功能需求

- **性能**：列表滚动 60fps；AI 摘要请求异步、不阻塞 UI，有加载与失败态。
- **离线**：核心读写在离线下可用，AI/同步功能离线时优雅降级并提示。
- **可访问性**：触摸目标 ≥48×48，支持系统字体缩放（现已支持），关键控件有语义标签。
- **国际化**：建立 i18n 框架，先支持中文/英文，消除现状中英文案混排。
- **兼容性**：Hive schema 升级保持向后兼容（沿用现有 typeId/字段编号约定）。

## 5. 隐私与安全（重点）

V2.0 引入云同步与 AI 后，应用会把**用户的文章 URL 与正文内容**发送到云后端和 LLM 服务，这是隐私敏感变更，必须满足：

- 首次启用云同步或 AI 功能时，明确弹窗告知数据将上传，用户主动同意后才开启（INF-6 / AI 同意）。
- 提供「纯本地模式」：不登录即可使用全部本地功能，AI/同步保持关闭。
- 传输全程 HTTPS；云端存储加密；账号删除时可一并删除云端数据。
- API 密钥不硬编码在客户端；AI 调用经由自有后端代理，避免密钥泄露。
- 不上传超出功能必需的数据，不做用户行为追踪式采集。

## 6. 成功指标（建议）

- 激活：新用户首周保存 ≥3 篇文章的比例。
- AI 价值：AI 摘要的使用率、「读摘要后未打开原页面」的占比（验证核心假设）。
- 留存：次周留存、跨设备使用账号占比。
- 质量：崩溃率 <0.5%，同步失败率 <1%。

## 7. 未决问题（需后续决策）

> 📊 调研已关闭部分问题，结论见下方标注。

1. **云后端选型**：托管 BaaS（Supabase / Firebase）还是自建？影响成本、隐私可控性与开发速度。（📊 优先级可后移——云同步需求集中于桌面小众场景）
2. **AI 调用架构**：客户端直连 LLM（密钥风险）还是经自有后端代理（推荐，但需服务端）。
3. **正文提取方案**：客户端提取（受反爬限制）还是服务端抓取（成本高但质量好），尤其微信/小红书。
4. **AI 成本控制**：自动摘要的 token 成本由谁承担？是否需要免费额度 + 订阅分层。
5. **商业模式**：📊 **调研给出方向**——愿付费人群为技术（67%）/ 研究（61%）工作者，与 AI 摘要高认可人群重合；50% 用户只用免费版。建议：**免费提供基础收藏/组织功能，AI 摘要 + 云同步作为面向专业用户的订阅项**。
6. ~~纯本地模式是否保留~~ 📊 **已决：保留**。59% 用户要求「本地/上传两种模式可自由切换」，仅 20% 愿无条件上传。本地优先 + AI/同步显式可选开关为确定设计。
