# 记忆海 实施路线图

> 配套文档：[`PRD.md`](./PRD.md) · 最后更新：2026-07-10 · 当前版本：V2.0.17

本路线图围绕仿生记忆的闭环推进：

```text
触摸采集 → 过滤提取 → 结构压缩 → 联想召回 → 引用追溯
   ↓            ↓           ↓           ↓           ↓
 可靠收集    自动知识化   本地索引    全库对话    知识共享
```

每个阶段必须能够独立验收。全文多 chunk 与多模态生成不属于当前主线。

## Phase 1 — 可靠的知识化流水线

**目标**：任何分享内容都先可靠保存，再异步转化为知识卡片；失败不会丢失，并能清楚重试。

**依赖**：当前本地存储、分享接收、元数据、正文提取和记忆能力。

### 1.1 数据模型与状态机

- [x] 为 `Article` 增加向后兼容的处理状态字段：
  - `processingStatus`：等待、处理中、完成、失败
  - `processingStage`：元数据、正文、记忆、标签、文件夹建议、索引
  - `processingError`
  - `retryCount`
  - 最后处理时间
  - `suggestedFolderId`
- [x] 手动更新 `ArticleAdapter.read/write`、field count、JSON 备份与回归测试
- [x] 将"知识库条目"和"待处理条目"的筛选规则固定下来

### 1.2 收集入口与待处理箱

- [x] Android 分享接收改为“先持久化，再导航/处理”，不要求用户完成添加表单
- [ ] 完成 iOS Share Extension 与冷启动、热启动接收
- [x] 新增待处理页，展示当前阶段、错误、重试和删除
- [x] 应用恢复前台后继续未完成任务
- [x] 增加 URL 去重与打开现有条目入口

### 1.3 自动知识化

- [x] 建立单一 processing pipeline，依次调用元数据、正文、记忆、自动标签和自动文件夹分类
- [x] 修正记忆兜底：正文提取失败时进入失败或等待状态，不把“基于标题猜测”当成可信知识卡片
- [x] AI 返回标签后自动写入；用户编辑过的标签不得被后续重记忆覆盖
- [x] AI 文件夹分类：直接写入 `folderId`，匹配现有文件夹则归类，否则自动创建新文件夹
- [x] 兼容 MiMo、DeepSeek、GPT-5、o1/o3/o4 等模型（chat() 按模型只发送一个 token 上限字段，剥离 `<think>` 标签）
- [x] 提供旧文章批量知识化入口，开始前显示条目数与 API 成本提示

### 1.4 测试与验收

- [x] 单元测试：状态迁移、重试计数、旧 Hive 数据读取、备份恢复
- [x] 服务测试：各阶段成功/失败时状态与错误正确（`test/processing_pipeline_test.dart`，覆盖 metadata/content/summary 三阶段成败、retry 计数推进）
- [x] Widget 测试：待处理空状态、处理中、失败、重试按钮（`test/inbox_screen_widget_test.dart`，6 个场景）
- [x] `MetadataService.parseHtmlMetadata` 单元覆盖（`test/metadata_service_test.dart`，15 个用例，含 og/twitter/title 优先级与相对 URL 解析）
- [ ] 设备验收：Android 与 iOS 分享后立即可见，断网或 AI 未配置时不丢失

**阶段验收标准**

- 分享接收持久化成功率达到 99% 以上；
- AI 未配置、断网、提取失败和 API 失败均进入可理解的进程状态；
- 成功条目自动获得记忆与标签；新文章被自动归类到合适文件夹（无匹配时自动新建）；
- 批量知识化不会未经用户确认产生 API 调用。

### 暂不处理

- 不做 embedding；
- 不重构首页；
- 不引入账号、后端队列或云同步。

## Phase 2 — 本地记忆索引与检索

**目标**：将每张知识卡片转成一个可在本地召回的记忆知识 chunk，为对话首页提供稳定检索层。

**依赖**：Phase 1 的可靠知识化状态与完成知识卡片。

### 2.1 Embedding 配置与能力检测

- [x] AI 设置增加独立的 embedding base URL、API Key、模型名称
- [x] 支持复用聊天服务凭证，但必须由用户显式选择
- [x] 调用兼容 embeddings endpoint 执行能力检测
- [x] 清楚展示配置缺失、模型不支持、鉴权失败和网络失败
- [x] 首次启用时说明记忆和查询将发送到用户选择的 embedding 服务

### 2.2 本地索引

- [x] 建立独立索引存储，不写入 `Article`，不进入 JSON 备份
- [x] 索引记录包含 `articleId`、模型标识、内容指纹和向量
- [x] 向量输入固定为标题、记忆和标签
- [x] 每个完成知识化的 Article 只产生一个索引记录
- [x] 新增、重记忆、标签变化、删除后增量更新索引
- [x] 导入备份、模型变化和索引损坏后支持全量重建
- [x] 删除孤立索引，禁止召回已不存在的 Article

### 2.3 召回与降级

- [x] 实现向量相似度召回与可配置 top-k
- [x] 建立最低相关度门槛，低于门槛返回无结果
- [x] embedding 不可用时按标题、记忆和标签执行关键词召回
- [x] 记录本次召回方式、耗时与候选 articleId，默认只保存在本地
- [x] 建立固定查询集，覆盖主题查询、同义表达、具体问题与无结果问题

### 2.4 测试与验收

- [x] 单元测试：向量输入、内容指纹、相似度排序、关键词降级、孤立索引清理
- [x] 集成测试：新增、重记忆、删除、导入后索引一致性
- [x] 安全测试：API Key 不进入账号同步、向量不进入备份；完整本地备份包含 Key 并有敏感文件提示
- [x] 固定查询集评估：预期相关文章稳定进入 top-k，无关问题返回无结果

**阶段验收标准**

- 所有完成知识化的条目都具备可检查的索引状态；
- Article 变化后不存在过期索引或失效引用；
- embedding 不可用时仍能完成关键词召回；
- 索引可删除并从知识卡片完整重建。

### 暂不处理

- 不切分正文；
- 不使用端侧 embedding 模型；
- 不生成最终 AI 回答。

## Phase 3 — AI 对话首页与新信息架构

**目标**：让用户从“浏览收藏列表”转向“向全部个人知识提问”，并通过引用回到知识卡片与原文。

**依赖**：Phase 2 的召回层。

### 3.1 新主导航

- [x] 文件夹页点击后导航回知识库并按文件夹过滤，知识库提供过滤 chip 可见与可清除
- [x] 保持路由恢复与 `ArticleResolver` 兼容

- [x] 对话首页支持主题词和具体问题
- [x] 查询先经过本地召回，再把候选记忆发送到用户聊天模型
- [x] 系统提示词强制只依据候选记忆回答
- [x] 模型输出使用结构化结果：回答、articleId 引用、信息不足状态
- [x] 过滤未知、重复或已删除的 articleId
- [x] 信息不足时明确拒绝编造，并展示可用的弱相关卡片

### 3.3 引用与反馈

- [x] 回答下方展示引用知识卡片
- [x] 引用卡片进入记忆页，并保留原文入口
- [x] 提供回答有用/无用反馈
- [x] 记录引用点击与成功知识召回，默认仅保存在本地
- [x] 提供无结果后的改写问题和浏览知识库入口

### 3.4 测试与验收

- [x] Widget 测试：空知识库、加载、带引用回答、信息不足、API 失败
- [x] 集成测试：引用 articleId 有效，点击后进入正确知识卡片

**阶段验收标准**

- 查询“汽车”等主题时能生成基于相关记忆的回答并展示引用；

- 对话失败不影响知识库浏览和待处理任务。

### 暂不处理

- 不做跨会话长期记忆；
- 不让模型访问互联网补充答案；
- 不做文件夹级报告、播客或 PPT。

## Phase 4 — 信任、自动化与扩展验证

**目标**：提高知识卡片与回答的可信度、自动化程度和可维护性，并基于行为数据决定下一步。

**依赖**：Phase 3 已产生真实知识召回行为。

### 4.1 质量与信任

- [x] 优化记忆提示词，优先保留关键事实、实体、数字、结论和主题词（V2.0.0，含 qualityRules、长度分档、中英文指令）
- [ ] 建立记忆有用率、对话无结果率、回答有用率和引用点击率看板
- [x] 增加索引健康检查（已显示索引数量）与批量重建（设置页 Rebuild Index 按钮）
- [ ] 允许用户查看本次召回方式与使用的记忆
- [ ] 根据反馈建立本地质量诊断，不默认上传用户行为

### 4.2 自动整理

- [x] 自动文件夹分类：AI 直接归类到现有文件夹或自动新建文件夹（V2.0.0）
- [ ] 优化自动标签的去重、合并和用户编辑保护
- [ ] 提供撤销/批量重新分类入口
- [ ] 根据已有文件夹与用户历史选择提高分类质量

### 4.3 扩展决策门槛

只有达到以下条件，才进入对应扩展：

| 候选扩展 | 启动条件 |
|---|---|
| 正文多 chunk | 大量无结果来自“记忆遗漏了原文细节”，且记忆优化无法解决 |
| 端侧 embedding | BYOK embedding 配置成为显著激活障碍，且端侧性能 PoC 可接受 |
| 云同步与账号 | 核心闭环成立，且跨设备需求通过行为或付费验证 |
| 文件夹级综述 | 用户持续对主题集合发起综合问题 |
| 社区记忆市场 | 记忆导出量达到临界规模，用户反馈跨人共享需求 |
| 商业化 | 专业用户的成功知识召回与留存显著高于基线 |

**阶段验收标准**

- 北极星指标“每周成功知识召回次数”可在设备本地计算；
- 能明确回答用户为什么没有得到结果；
- 新扩展由行为证据触发，而不是继续堆叠功能。

### 暂不处理

- 不预先承诺具体云后端或订阅价格；
- 不因竞争产品功能而扩展范围；
- 不改变本地优先与 BYOK 的硬约束。

## 3. 全阶段工程约束

- `Article` 类名、Hive typeId `0` 和 `'passages'` box 名称必须保留。
- 所有 Hive 新字段均手写 adapter，使用新字段编号并兼容旧记录。
- SourcePlatform 继续使用显式稳定整数映射，禁止使用 enum `.index`。
- 向量索引属于可重建派生数据，不进入备份。
- API Key 必须保持设备本地，不得进入同步 payload、shadow、冲突记录或服务端；服务端还必须过滤旧客户端并迁移清理历史副本。
- 任何后台处理都必须可取消、可重试，并避免阻塞 UI。
- 每个阶段结束前运行：

```bash
flutter analyze
flutter test
```

涉及 Android/iOS 分享入口或真实 AI 服务的阶段，还必须在真机完成手工验收。

## 4. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 微信、小红书等平台正文提取失败 | 无法生成可信知识卡片 | 保留待处理状态与原文入口，不根据标题臆测 |
| 用户模型不支持 embeddings | 无法语义召回 | 能力检测 + 关键词降级 |
| 记忆作为单一 chunk 丢失细节 | 具体问题无结果 | 明示记忆边界，先优化记忆；用行为证据决定是否引入正文 chunk |
| BYOK 配置门槛高 | 大众用户无法立即体验 AI | 允许先收集到待处理箱，提供清晰配置检查 |
| 本地索引损坏或模型变化 | 召回错误或不可用 | 内容指纹、健康检查与全量重建 |
| AI 回答产生无效引用 | 用户信任受损 | 结构化输出、articleId 白名单过滤、信息不足拒答 |
| API 成本不可控 | 用户意外消费 | 自动处理开关、批量操作前成本提示、避免重复记忆与 embedding |
| 云端同步数据泄露 | 用户隐私风险 | HTTPS、严格账号隔离、最小权限、敏感字段不写日志、数据库与备份访问审计 |
| 订阅转化率低 | 无法覆盖运营成本 | 核心功能永久免费，高级能力分层付费；持续验证付费意愿 |
