# Article-Hub 实施路线图（ROADMAP）

> 配套文档：`docs/PRD.md` · 最后更新：2026-06-02 · 起点版本：V1.5.0

> 📊 **本路线图已依据用户调研调整阶段顺序**（107 份样本，详见 [`调研分析报告.md`](./调研分析报告.md)）：**组织/录入类基础功能提前、云同步后移、AI 摘要重定位为面向专业用户的付费能力**。调整原因见下方各阶段 📊 标注。

本路线图把 V2.0 愿景拆成可独立交付的阶段。每个阶段都能单独发版，越靠前价值/风险比越高。阶段之间存在依赖：**正文提取 → AI 摘要**、**账号 → 云同步**。

---

## 阶段总览

> 📊 调研后顺序：基础组织/录入（原 Phase 1+3）提前，AI（原 Phase 2）作为付费亮点紧随其后但不再是唯一主线，云同步（原 Phase 4）后移。

| 阶段 | 主题 | 目标版本 | 依赖 | 核心价值 |
|------|------|---------|------|---------|
| Phase 0 | 技术债清理 + 数据安全 | V1.6 | 无 | 修崩溃风险、补本地备份、立测试底座 |
| Phase 1 | 录入入口 + 组织升级 📊 | V1.7 | 无 | 系统分享接收、文件夹+标签、自动标题封面（**调研 Top2 功能**） |
| Phase 2 | 内容提取 + AI 阅读中枢 | V1.8 | Phase 1 | 正文提取 + AI 摘要，**定位为面向专业用户的付费亮点** |
| Phase 3 | 检索与状态增强 | V1.9 | 无 | 强搜索、批量操作、阅读状态 |
| Phase 4 | 账号 + 云同步 📊（↓后移） | V2.0 | 无 | 多设备同步，**主要服务桌面用户，需求相对小众** |
| Phase 5 | 界面升级 + 体验打磨 | V2.x | 贯穿全程 | 信息架构重构、响应式、i18n |

> 顺序建议：Phase 0 必须先做。**📊 调研后主线为 Phase 1（组织+录入，得票最高）→ Phase 2（AI，面向专业用户付费）**。Phase 3 可并行插入。**Phase 4 云同步因需求集中于桌面小众场景而后移**，资源紧张时可只服务核心移动场景。Phase 5 界面升级随各阶段渐进落地，V2.0 集中收口。

## Phase 1 — 导入入口 + 内容增强（V1.7）

**目标**：降低保存成本、提升每条收藏的信息密度，并为 AI 摘要铺好正文提取的前置依赖。

- [ ] IMP-1：注册系统分享目标，从其他 App 分享链接直接保存（移动端核心入口，Android `intent-filter` + iOS Share Extension）
- [x] IMP-2：批量粘贴多条 URL（换行/空格/逗号/分号分隔）一次保存（`parseUrlList` + `addMany` + 添加页批量 sheet）
- [x] IMP-6：进入/回到前台时自动检测剪贴板链接，弹 SnackBar 提示一键添加（设置可关，默认开；HomeScreen 生命周期监听 + `clipboardDetectionEnabled`）
- [ ] READ-5：保存时抓取 `og:title` / `og:image`，自动填充标题与封面缩略图
- [ ] AI-1：正文提取服务（去广告/导航留正文），失败回退 WebView——**Phase 2 的前置依赖**
- [ ] 列表卡片支持封面缩略图展示

**验收**：从微信/浏览器分享链接可一步保存；保存后自动带标题与封面；正文提取在主流平台成功率达标。

## Phase 2 — AI 阅读中枢（V1.8，核心差异化）

**目标**：实现「用 AI 总结代替打开原页面」，这是 V2.0 最大卖点。

- [ ] AI-7：搭建 AI 调用层（**BYO 模式：用户自带 API key，密钥仅存本地、不经任何服务器**；默认最新 Claude Opus/Sonnet 4.x）
  - 说明：本应用为「用户自带密钥」模型，每位用户填写自己的 key。密钥本地存储优于后端代理——key 不经过我们的服务器，我们无需替用户保管密钥、也不承担集中泄露责任，隐私更干净。这与「开发者共享密钥必须藏后端」是不同威胁模型，不可混用。
- [x] AI-8：密钥存储与备份隔离——key 存于本地 Hive（`AppSettings.aiApiKey`），**不在传输路径上**（应用直连用户自己的 AI 提供商，不经任何中间服务器）。**不做额外静态加密**：威胁模型为「攻击者拿到已解锁设备或 root 权限」，此场景下 app 内加密无实质防护（解密路径就在同一 app 内）。唯一有意义的防护已落地——**备份导出排除 key 字段**（`AppSettings.toJson` 不含 `aiApiKey`，有回归测试守护），避免明文 key 随可分享的 JSON 备份外泄；导入备份后提示用户重新填写 key。
  - 设计权衡：曾尝试用 `flutter_secure_storage`（Keychain/Keystore）加密，但其 web 子包依赖 `dart:html`/`dart:js_util`，与 Flutter 3.41 默认 Wasm 渲染器不兼容，导致 web 端白屏。鉴于上述威胁模型分析（加密收益边际、代价是 web 不可用 + 多平台条件导入复杂度），决定回退为明文本地存储，保留备份排除这一唯一有效防护。详见 [`docs/PRD.md`](./PRD.md) AI key 存储决策。
- [ ] AI-2：结构化摘要生成（一句话总结 + 要点列表）
- [ ] AI-4：摘要随文章缓存，避免重复消耗 token
- [ ] READ-1：全新摘要阅读页——先摘要，后「展开正文 / 打开原页面」
- [ ] AI-3：保存时自动摘要 / 手动触发，设置可选
- [ ] INF-6：AI 功能首次启用的隐私同意弹窗
- [ ] AI-5（可选）：单篇文章 AI 追问
- [ ] AI-6（可选）：摘要语言选择

**验收**：保存后能看到可信摘要；摘要阅读页流畅；隐私同意流程合规；**API key 不随备份导出**；token 成本在预算内。

## Phase 3 — 组织与检索升级（V1.9）

**目标**：从「一堆收藏」升级为「可管理的知识库」。与 AI 主线独立，可并行。

- [ ] ORG-1：文件夹/收藏夹（支持嵌套）

- [ ] ORG-4：搜索结果关键词高亮、多维排序、搜索历史
- [ ] ORG-6：已读/未读/稍后读状态与筛选
- [ ] ORG-2（可选）：嵌套标签

**验收**：可用文件夹组织文章；批量操作流畅；搜索体验明显增强。

## Phase 4 — 账号 + 云同步（V2.0）

**目标**：多设备同步，本地 Hive 转为离线缓存层。工作量最大、需先定后端选型（PRD 未决问题 1）。

- [ ] 决策：云后端选型（BaaS vs 自建）——**启动前必须先定**
- [ ] INF-1：账号体系，匿名本地数据可平滑迁移上云
- [ ] INF-2：文章/标签/文件夹/设置云同步
- [ ] INF-3：离线优先 + 增量同步 + 冲突按最后修改时间合并
- [ ] INF-5：同步状态可视化与手动重试
- [ ] 隐私：账号删除可一并清除云端数据

**验收**：两台设备数据一致；离线可用、联网自动合并；同步失败率 <1%。

## Phase 5 — 界面升级 + 体验打磨（贯穿全程，V2.0 收口）

界面升级不单独排期，而是随各阶段渐进落地，在 V2.0 集中收口。重点：

**信息架构重构**
- 引入底部导航：首页 / 稍后读 / 文件夹 / 设置（替代当前单页 + 角落按钮）
- 首页支持卡片流 / 紧凑列表切换；封面缩略图融入卡片

**新增/重构界面**
- 摘要阅读页（Phase 2）：摘要卡片 + 正文展开 + 原页面入口
- 文件夹管理页（Phase 3）
- 批量操作的多选模式工具栏
- 同步状态指示（Phase 4）
- 登录/账号页（Phase 4）

**体验打磨**
- i18n 框架，消除中英文案混排（先中/英双语）
- 可访问性补齐：触摸目标、语义标签、对比度
- 桌面/Web 响应式：宽屏双栏（列表 + 阅读），键盘快捷键（移动为主，此项为辅）
- 延续现有动画语言（转场、逐项揭示），保持品牌一致性

**验收**：导航与信息架构清晰；新界面与现有设计语言统一；中英文均无混排；宽屏布局可用。

## 风险与依赖提示

| 风险 | 影响 | 缓解 |
|------|------|------|
| 正文提取对微信/小红书等反爬平台成功率低 | AI 摘要质量受限 | 评估服务端抓取；失败优雅回退 WebView |
| AI token 成本不可控 | 运营成本 / 需商业模式 | 摘要缓存、按文长选模型、自动摘要设额度 |
| 云后端选型影响深远 | 架构返工成本高 | Phase 4 启动前完成选型与 PoC |
| 隐私合规（上传 URL/正文） | 用户信任 / 合规 | 明确同意流程 + 纯本地模式兜底 |
