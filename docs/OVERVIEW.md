# Article-Hub 产品介绍

> 一个跨平台的「文章收藏 + 阅读」应用 · 当前版本 V1.5.0
> 配套文档：产品需求见 [`PRD.md`](./PRD.md)，演进规划见 [`ROADMAP.md`](./ROADMAP.md)

---

## 一句话介绍

Article-Hub 是一个把你散落在 X、Bilibili、小红书、微信、知乎、ChatGPT、YouTube 等平台的链接，一处收集、统一管理、随时回看的应用。粘贴链接即可保存，应用自动识别来源平台，配上标签、备注和收藏，再用内置阅读器随时打开——让"想存起来以后看"的内容真的能被找回来。

---

## 它解决了什么痛点

现代人的优质内容被切碎在十几个互不相通的 App 里，"收藏"这件事本身是破碎的：

| 痛点 | 现状的麻烦 | Article-Hub 的解法 |
|------|-----------|-------------------|
| **收藏分散在各平台** | 微信的收藏、B站的稍后看、X 的书签、浏览器的标签页……分散在十几个地方，没有一个统一入口 | 不管来自哪个平台，链接粘进来就统一沉淀在一处 |
| **存了就忘、找不回** | 平台收藏夹没有标签、没有备注，存几十条之后就再也翻不到想要的那条 | 标签 + 备注 + 全文搜索 + 自定义筛选组，按自己的方式组织和检索 |
| **不知道这条是哪来的** | 一堆裸链接，分不清是文章、视频还是帖子 | 自动识别 11 个来源平台，用图标、颜色、短标签一眼区分 |
| **跳来跳去打断阅读** | 点开收藏要在多个 App 之间反复横跳 | 内置阅读器直接在应用内打开，必要时一键转系统浏览器 |
| **数据被平台绑架** | 收藏的内容存在别人的服务器上，平台关停或限制就没了 | 数据本地存储（Hive），完全属于你自己 |

核心价值可以浓缩成一句：**把"碎片化收藏"变成"可检索、可回看的个人内容库"。**

## 目标用户

- **信息重度消费者**：每天从多个平台收集文章、视频、帖子，需要一个统一的沉淀池。
- **知识管理者**：习惯给内容打标签、写备注，建立自己的检索体系。
- **跨场景读者**：刷到时先存下，通勤、睡前等有空时再集中阅读。

---

## 核心功能

### 1. 一步保存，自动识别来源
粘贴任意链接，应用通过域名自动判断来源平台，目前支持 **11 个平台**：

微信公众号 · 知乎 · X(Twitter) · Bilibili · 小红书 · ChatGPT · YouTube · Medium · Substack · Reddit · 通用网页

每个平台有专属图标、品牌色和短标签（如知乎「知乎」、B站「B站」、X「X」），列表里一眼可辨。

### 2. 组织：标签 + 备注 + 收藏
- 自由打标签，给每条内容加上下文
- 写备注记录"为什么存它"
- 星标收藏重要内容
- 自动记录保存与更新时间

### 3. 检索：搜索 + 筛选 + 自定义筛选组
- 跨**标题、标签、备注、URL** 的全文搜索
- 按来源平台一键筛选
- **自定义筛选组**：把"标签关键词 + 来源平台"的组合存成一个筛选器，比如"技术类的 B站+YouTube 视频"，一次点击直达

### 4. 阅读：内置阅读器
- 应用内 WebView 直接打开，不跳出 App
- 移动端 UA、缩放控制、加载进度条
- 智能拦截 App 深链跳转（如微信、应用商店唤起），避免阅读被打断
- 一键转系统浏览器作为兜底

### 5. 个性化
- 浅色 / 深色 / 跟随系统三种主题
- 全局字号调节
- 阅读器默认缩放比例可调
- 来源平台 chip 可拖拽排序、可隐藏——只展示你常用的平台

---

## 产品特点

- **本地优先，隐私友好**：数据用 Hive 存在设备本地，不上传、不追踪，内容完全自有。
- **流畅精致的体验**：页面转场、列表逐项揭示等动画经过打磨，交互顺滑。
- **完整的深浅色支持**：两套主题都精心配色，夜间使用不刺眼。
- **跨平台**：基于 Flutter，一套代码覆盖 Android、iOS、Windows、macOS、Web。

## 技术架构

| 层面 | 选型 | 说明 |
|------|------|------|
| 框架 | Flutter (Dart 3.11) | 跨平台，单一代码库 |
| 状态管理 | Riverpod | 声明式、可测试的状态管理 |
| 本地存储 | Hive | 轻量级 NoSQL，手写 TypeAdapter 保证 schema 向后兼容 |
| 路由 | go_router | 声明式路由，自定义转场动画 |
| 阅读器 | flutter_inappwebview | 应用内浏览，深链拦截 |

**代码组织**（feature-first 分层）：
```
lib/
├── config/        # 主题、路由
├── data/          # 数据模型、仓库
│   ├── models/    # Article、SourcePlatform、AppSettings、FilterGroup
│   └── repositories/
├── features/      # 按功能划分的页面
│   ├── home/      # 首页（列表、搜索筛选）
│   ├── add_passage/  # 添加文章
│   ├── detail/    # 详情编辑
│   ├── reader/    # 内置阅读器
│   └── settings/  # 设置
└── shared/        # 跨功能共享的 providers、工具、组件
```

## 当前状态与演进方向

**当前（V1.5.0）**：功能完整的本地收藏管理工具，已经能很好地解决"统一收集 + 组织检索 + 应用内阅读"。

**下一步**：从"本地收藏工具"升级为"跨设备 + AI 阅读中枢"，三个主要方向——

1. **AI 阅读中枢**（核心差异化）：自动提取正文并生成 AI 摘要，让你**不必打开原页面就能读完核心内容**。
2. **多设备云同步**：账号体系 + 云端同步，手机收藏、平板/桌面阅读，数据不再受限于单台设备。
3. **更强的组织与导入**：文件夹、批量操作、系统分享菜单接收链接、自动抓取标题与封面。
