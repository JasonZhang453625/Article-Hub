# 记忆海 产品介绍

> 仿生记忆提取 · AI 信息强化 · Agent-friendly 知识存储
> 产品需求见 [`PRD.md`](./PRD.md)，实施计划见 [`ROADMAP.md`](./ROADMAP.md)

---

## 产品理念

人类的记忆从来不靠"全量保存"。大脑会自动过滤噪声、提取结构、保留关键概念，并在需要时通过联想完成回忆——一条模糊的印象就足以唤起整段经历。记忆海把这套认知逻辑映射到数字内容上：

- **仿生记忆提取**：不保存整页广告、推荐流和平台 UI。从每篇文章中提取核心骨架——标题、关键观点、标签与原文入口——像大脑记住"这件事很重要"一样，只保留内容中信息密度最高的那一层。
- **信息密度 AI 强化**：原页面结构松散、信息稀释。经过 AI 记忆后，一篇万字长文被压缩为一组高密度知识颗粒——一条知识卡片就是一个可直接调用的记忆单元。
- **Agent-friendly 标准化知识存储**：所有内容统一转化为"结构化记忆 + 向量索引"的知识卡片格式。不是只有人才能浏览——AI Agent 也能做语义召回、推理和问答。你的知识库既是个人记忆，也是可被 Agent 调用的认知资源。

> **一键分享即知识化。对话即联想检索。原文始终可追溯。**
>
> 你不需要记住"保存在哪"，只需要知道自己"学过这个"。

## 一句话介绍

记忆海 把散落在微信、知乎、Bilibili、小红书、X、YouTube 等平台的内容，通过系统分享入口自动转化为统一的 AI 记忆知识卡片，并让用户直接向自己的全部知识库提问。

## 它解决什么问题

用户每天都在不同平台看到值得保存的内容，但“收藏”通常只完成了存放，没有完成再次使用：

| 问题 | 常见结果 | 记忆海 的解法 |
|---|---|---|
| 内容分散在不同 App | 想找时记不起在哪个平台 | 从系统分享入口统一接收 |
| 原页面结构混乱 | 广告、推荐与平台 UI 干扰阅读 | 转成统一、简洁的知识卡片 |
| 保存后缺少整理 | 手工标签和文件夹成本高 | 自动标签，文件夹只给建议 |
| 只记得概念，不记得标题 | 普通标题搜索找不到 | 对全部记忆进行语义召回 |
| AI 回答难以核实 | 不知道结论来自哪里 | 回答附带知识卡片引用和原文入口 |
| 担心内容上传和锁定 | 数据受平台控制 | 本地存储、本地索引、BYOK、可导出 |

记忆海 的目标不是帮助用户保存更多，而是模拟记忆的工作方式——过滤噪声、提取结构、建立联想——让保存过的内容在需要时能够再次被唤起和使用。

## 核心闭环

```text
跨平台分享链接
  → 进程页
  → AI 记忆知识卡片
  → 自动标签 + 自动文件夹分类
  → 本地向量索引
  → 首页全库对话
  → 引用知识卡片
  → 原文追溯
```

### 1. 分享：低摩擦进入

用户在其他 App 中点击“分享到 记忆海”。应用第一时间保存链接，再执行后续处理。即使网络断开、AI 未配置或正文提取失败，内容也不会丢失，而是留在进程页等待重试。

### 2. 知识化：统一内容单位

不同来源的页面被转换成统一知识卡片。V2.0 首版中：

- 一篇内容对应一个 AI 记忆知识卡片；
- 一个记忆知识卡片对应一个检索 chunk；
- 记忆用于快速理解和全库召回；
- 原页面用于核实与深入阅读。

### 3. 自动整理：弱结构自动，强结构确认

- AI 自动生成标签，用户可以编辑；
- AI 推荐最合适的已有文件夹；
- 文件夹移动必须由用户确认，避免模型误分类破坏知识库结构。

### 4. 对话：从翻找变为提问

新版首页不是文章列表，而是面向全部已知识化内容的对话入口。用户可以问：

- “汽车”
- “我收藏过哪些关于新能源汽车竞争格局的观点？”
- “这些内容对本地 AI 有哪些共同判断？”

系统先从本地索引召回相关记忆，再让用户配置的模型基于这些记忆回答，并展示可点击引用。

### 5. 追溯：回答不是终点

每个回答都必须引用真实知识卡片。用户可以从回答进入记忆卡片，再打开原页面。记忆中不存在的事实不得被模型补写；信息不足时应明确提示。

## 产品差异化

记忆、RAG 和语义检索不是独有功能。记忆海 的差异化在于完整工作流：

1. **中文互联网与移动分享入口**：从微信、小红书、知乎、Bilibili 等用户实际使用的平台直接接收链接。
2. **分享后自动知识化**：把不同平台页面转成一致的个人知识单元，而不只是保存 URL。
3. **默认全库对话**：不要求用户先创建 notebook 或选择资料集，直接检索全部个人内容。
4. **本地优先与 BYOK**：内容、处理状态与索引默认保存在设备本地；AI 请求直连用户选择的服务。登录后的跨设备同步为可选能力，只同步 AI/Embedding 模型与 Base URL 等非敏感设置；API Key 保持设备本地。
5. **回答可追溯**：每个回答都回到已保存知识卡片和原页面。
6. **记忆可共享**：导出知识卡片集为标准格式，分享给他人或 Agent 加载；所有权永归个人。

记忆海 不以取代 NotebookLM 式研究工具或 Readwise 式深度阅读工具为目标，而是优先解决内容进入个人记忆之前的低摩擦收集、仿生提取和全库联想召回。

## 信息架构

当前移动端主导航：

| 入口 | 作用 |
|---|---|
| **对话** | 向整个知识库提问，查看带引用回答 |
| **知识库** | 浏览、搜索和整理知识卡片 |
| **进程** | 查看处理中、失败和等待配置的内容 |
| **设置** | 配置 AI、embedding、隐私、备份、索引与账户同步 |

传统文章列表、文件夹、标签和关键词搜索不会消失，而是统一进入知识库页。

## 当前已经实现

截至 2026-07-10（V2.0.17），当前代码已经具备 仿生记忆方向所需的主要基础：

- 纯本地 Hive 存储；
- 11 类来源识别；
- 单条和批量 URL 添加；
- 剪贴板检测与 Android 系统分享接收；
- 页面标题、封面和正文提取；
- 用户自带 OpenAI-compatible API 的记忆生成；
- 记忆优先知识卡片页与原页面 WebView；
- 标签、备注、收藏、文件夹和嵌套文件夹；
- 搜索、来源筛选和自定义筛选组；
- JSON 完整备份恢复（包含本机 provider Key，导出文件须安全保管）；
- 中英文多语言支持（系统/中文/英文）与 AI 记忆语言指令注入；
- 字体大小与 WebView 缩放可调；
- 来源平台排序、隐藏与首页筛选栏拖拽重排；
- 记忆反馈字段（thumbs up/down，重记忆时自动重置）；
- 全局入场动画（DelayedReveal）；
- **处理状态机**：Article 新增 processingStatus / processingStage / processingError / retryCount / lastProcessedAt / suggestedFolderId，Hive field 13-18，旧数据自动降级为 completed；
- **先保存再处理**：分享链接立即持久化为 pending 状态，后台 pipeline 异步处理，URL 去重；
- **进程页**：原“待处理箱 / Inbox”，展示 processing / pending / failed 分组，显示阶段、错误、重试和删除，前台恢复自动重试；
- **5 阶段处理流水线**：metadata → content extraction → AI summary → auto-tags → auto folder classification，每阶段状态持久化，失败不丢失；
- **自动标签与自动文件夹分类**：AI 返回标签自动写入（不覆盖用户编辑），文件夹直接归类到现有文件夹或自动新建；
- **思考模型兼容**：MiMo / DeepSeek / o1 / o3 等思考模型自动适配（关 thinking 或保留思考预算，剥离 `<think>` 标签）；
- **文件夹过滤 chip**：知识库页显示当前文件夹过滤，点击 chip 可清除；从文件夹页点击条目可一键切换到对应文件夹视图；
- **旧文章批量知识化**：Settings 页入口，显示条数与 API 成本提示，需用户确认；
- **Embedding 配置与本地向量索引**：独立 embedding baseUrl/apiKey/model 配置，Key 不进入账号同步但会进入用户主动导出的完整备份；Hive 独立 box (typeId=6)，一篇一记录，增量更新+全量重建；
- **向量召回与关键词降级**：cosine similarity top-k 召回，最低门槛过滤，embedding 不可用时降级为标题+记忆+标签关键词召回；
- **四入口底部导航**：Chat / Knowledge / Progress / Settings，StatefulShellRoute 保持各 tab 状态；
- **RAG 对话首页**：查询→本地召回→候选记忆发送聊天模型→回答+引用知识卡片 ActionChip，信息不足时明确拒绝编造。
- **TXT/MD 文件导入**：从文件管理器选择文本或 Markdown；提取 Markdown 标题、规范化正文，并跳过网页抓取直接进入知识化流程。
- **账户与自动同步**：邮箱验证码登录、会话持久化、账户页手动同步，以及登录后/恢复前台/网络恢复时的自动同步。
- **非敏感配置同步**：文章、文件夹、筛选组和应用设置通过本地 outbox 增量同步；AI/Embedding 的 Base URL 与模型随账号同步，五类 provider API Key 在 outbox、shadow、冲突记录和网络出口统一剔除。
- **大屏布局**：宽度达到平板断点时，底部导航切换为侧栏导航。

## 隐私与数据所有权

- Article、标签、文件夹、记忆和处理状态保存在设备本地；
- 核心知识库默认保存在本机；可选账号同步会把选定实体通过 HTTPS 发送到记忆海服务端，当前负载未做端到端加密；
- BYOK AI 与 embedding 请求直连用户配置的服务；Hosted Agent 请求经记忆海后端执行；
- API Key 不进入账号同步；仅用户主动创建的完整本地备份可以包含 Key；
- 未来向量索引属于可重建派生数据，也不进入备份；
- 用户可导出并恢复自己的核心知识库数据。

## 当前产品押注

107 份用户问卷已经验证“收藏分散”和“保存后很少回看”是真实问题，也支持系统分享入口、本地优先和整理能力的重要性。

仿生记忆方向 新方向仍需要验证。产品接下来的关键问题不是“用户是否觉得 AI 记忆听起来有用”，而是：

> **用户是否会持续通过对话找回并使用自己保存过的内容？**

北极星指标因此定义为 **每周成功知识召回次数**：用户通过对话得到带引用的回答，并通过有用反馈或引用点击证明结果产生了价值。

## 记忆共享

知识不应当只锁在一人之脑中。记忆海支持用户将个人知识库导出为标准化的记忆卡片，并自由分享给他人：

- **导出个人记忆**：一键将知识卡片、标签、文件夹结构导出为标准格式（JSON / OKF），脱离应用本身仍然可用。
- **社区共享记忆**：把精选的知识卡片集分享给团队、社群或公开社区——就像把自己阅读过的内容、提炼出的观点和建立的分类体系"开源"给他人。
- **Agent 可直接消费**：导出的记忆包采用 Agent-friendly 格式，可以导入其他人的记忆海，也可以直接被外部 AI Agent 作为知识库加载。
- **所有权永归个人**：导出内容是用户的私有财产。选择分享时，分享的是你提炼后的知识结构，而不是原始平台数据。分享授权、范围和用途完全由你决定。
